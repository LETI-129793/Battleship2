## 1. Regra selecionada

Foi selecionada a regra `ConstantName` do Checkstyle, responsável por verificar os nomes das constantes Java.

A expressão regular utilizada é:

`^[A-Z][A-Z0-9]*(_[A-Z0-9]+)*$`

Esta regra exige que os nomes das constantes sejam escritos em letras maiúsculas, podendo conter números e underscores (`_`) para separar palavras, seguindo a convenção `UPPER_SNAKE_CASE`.

O ficheiro de configuração é `checkstyle-129793.xml`, localizado na raiz do projeto.

## 2. Integração com GitHub Actions

Foi criado o workflow `.github/workflows/checkstyle-129793.yml`, que executa o Checkstyle através da ação `dbelyaev/action-checkstyle@v1.12.0` quando é aberto ou atualizado um Pull Request, permitindo também a execução manual.

O workflow utiliza a configuração individual do aluno e falha quando são detetadas violações da regra definida.

## 3. Teste com violação — Failure

Foi criado o ramo `teste-constant-name-129793` e o Pull Request [#19](https://github.com/LETI-129793/Battleship2/pull/19).

Na classe `TesteConstantName129793.java`, foi introduzida deliberadamente a constante `maxShips`, que não respeita a convenção de nomes definida.

O Checkstyle identificou a violação da regra `ConstantName` na linha 6, uma vez que o nome da constante não correspondia à expressão regular configurada.

**Evidência:** [GitHub Actions — Failure](https://github.com/LETI-129793/Battleship2/actions/runs/42680055669)

## 4. Correção da violação — Success

A constante foi renomeada de `maxShips` para `MAX_SHIPS`, respeitando a expressão regular definida.

Após o commit e o push da correção, o workflow foi executado novamente e terminou com sucesso.

**Evidência:** [GitHub Actions — Success](https://github.com/LETI-129793/Battleship2/actions/runs/42681324143)

## 5. Limitações da regra

A regra `ConstantName` verifica apenas se os nomes das constantes respeitam o padrão definido, não conseguindo avaliar se esses nomes são claros ou significativos.

Por exemplo, uma constante chamada `ABC` respeita a expressão regular, mas pode não transmitir corretamente o seu significado.

Além disso, o Checkstyle não consegue determinar se o nome escolhido descreve adequadamente a finalidade da constante no programa.

O Checkstyle foi assim integrado como Quality Gate obrigatório no processo de validação dos Pull Requests.
