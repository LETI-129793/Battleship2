# Checkstyle — Quality Gate 129785
**Aluno:** Guilherme Lopes — **129785**  
**Projeto:** Battleship2  
**Tarefa:** 2B — Verificação de convenções de nomes (Variáveis Locais)  

## 1. Regra selecionada
Foi selecionada a regra `LocalVariableName` do Checkstyle, responsável por verificar os nomes das variáveis locais em Java.  
A expressão regular utilizada é:  
`^[a-z][a-zA-Z0-9]*$`  
Esta regra exige que os nomes das variáveis locais comecem por uma letra minúscula e contenham apenas letras e números, seguindo o padrão *camelCase* clássico.  
O ficheiro de configuração é `checkstyle-129785.xml`, localizado na raiz do projeto.  

## 2. Integração com GitHub Actions
Foi criado o workflow `.github/workflows/checkstyle-129785.yml`, que executa o Checkstyle através do Maven quando é aberto ou atualizado um Pull Request.  
O workflow utiliza a configuração individual do aluno e falha quando são detetadas violações da regra definida.  

## 3. Teste com violação — Failure
Foi criado o ramo de teste correspondente e o Pull Request associado.  
Na classe criada para o efeito (ex: `Pontuacao.java`), foi introduzida deliberadamente uma variável local com um nome incorreto, como `int VariavelIncorreta = 10;`, violando a convenção de letras minúsculas iniciais.  
O Checkstyle identificou uma violação da regra `LocalVariableName` e o workflow terminou com `BUILD FAILURE`.  
*Evidencia:* https://github.com/LETI-129793/Battleship2/commit/2834f49


## 4. Correção da violação — Success
A variável local foi renomeada para `int variavelCorreta = 10;`, respeitando a expressão regular definida.  
Após o commit e o *push* da correção, o workflow foi executado novamente e terminou com sucesso.  
*Evidência:* https://github.com/LETI-129793/Battleship2/commit/f6dcb4a

Ambos os pontos 3 e 4 estão no mesmo Pull request com 2 commits, o primeiro referente à falha e o segundo referente ao sucesso https://github.com/LETI-129793/Battleship2/pull/17#issue-6272508252

## 5. Limitações da regra
A regra `LocalVariableName` verifica apenas a conformidade sintática e o padrão de caracteres das variáveis locais, não conseguindo avaliar se o nome escolhido é verdadeiramente significativo ou se descreve com precisão o contexto do dado armazenado. Além disso, a validação não consegue distinguir variáveis puramente temporárias de variáveis de negócio mais complexas.  

## 6. Proteção do ramo principal
A configuração de proteção do ramo `main`, para tornar o Checkstyle obrigatório antes de um *merge*, ficou por realizar. Esta configuração depende da coordenação com o administrador do repositório partilhado e da identificação inequívoca do check correspondente.
